## 1. 固定边界与规则所有权

复用主设计第 1、4–9 节的定位、分类、七层、安全确认、适用性、交付目标及风险裁剪，不另写第二套业务判定。`.codex` 是内容基线；`.agents` 继续隐藏/禁用且不删除。路由迁移不改变个人交互偏好或静默撤销能力。

下表规定规则责任。A 阶段须把每个规则域映射到唯一规范文件及校验入口；结构规则与解释投影分开登记。准确运行文件由详细计划核对实际源码后固定，未完成登记不得进入 C。

| 规则域 | 责任组件 | 产品语义权威 | 必须收敛的运行规范 |
| --- | --- | --- | --- |
| 分类、入口与确认 | Goal | 主设计第 1、4、7 节 | 分类协议字段与分类策略各只有一处定义，Harness 交接引用 |
| 交付契约与修订 | Goal | 主设计第 5、5.1 节 | 单一契约 schema 和修订/确认规则，模板只作投影 |
| 层门、回退与执行加载 | Harness | 主设计第 4.2、7 节 | 唯一层门/加载规则；checklists、exit/reentry 不另设竞争门槛 |
| 验收与证据 | Harness | 主设计第 6、8 节 | 单一验收规则；纯校验器检查机器不变量，Guard 不判断业务正确性 |
| Closure | Harness | 主设计第 9 节 | 唯一 Closure 规则与结构，Goal 展示引用，不再平行维护输出规范 |
| 状态兼容与转换 | Guard | 主设计第 4.1、8.3、12 节 | 保留转换/锁/原子写入路径，记录协议差异，不造第二事实源 |

## 2. 同一实施链中的工作包

### A. 交付契约与纯校验

- [ ] 核对源摘要和真实维护/安装来源；建立规则权威映射，含规则 ID、责任组件、规范文件、引用/生成消费者及漂移校验入口。
- [ ] 同步设计契约纯校验和兼容测试；精确字段、状态、枚举、确认记录、引用完整性及容量边界沿用主设计，不以关键词代替。
- [ ] 清点重复规范和措辞耦合测试，区分不可放松的结构/安全约束与可等价改写的解释；不先改弱断言。
- [ ] 按第 3 节重测改进前三个阶段，保存源码摘要、去重必读清单、触发原因及工具版本，不复用旧审计数字充当测量。

交接物：契约及纯校验测试、权威映射、旧运行回归清单、改进前加载清单与测量结果。详细计划指定准确文件、命令、预期结果和检查点；未运行不填通过。

### B. Guard 增量约束与旧运行兼容

- [ ] 只按主设计第 4.1、8 节接入 `delivery`：显式 feature 检查、新运行初始化绑定、禁止活动降级、旧状态兼容及有界写入/证据一致性约束。
- [ ] 回归缺能力、旧运行、删扩展、过量候选及失败保留原状态；Windows 保持 `audit-only-windows`，不声称机械拦截或诚实执行证明。
- [ ] 对齐 `classified -> executing` 与 Guard 相邻转换差异，记录接口选择和测试证据；major 相同不代表行为兼容。
- [ ] 受 Foundation/Adapter 并行工作影响的接口先审差异再接入；允许上述 Guard 增量，不建设 Fast Run、Provider 平台或完整 state schema v2。

交接物：已验证增量能力契约、新旧状态兼容结果和未解决差异。不得用未知来源安装文件替代已检查维护源码。

### C. Goal/Harness 接入与结构收敛

- [ ] 单一集成负责人一次纳入 Web 全栈入口、契约接入、重复规则收敛和条件路由迁移，不先堆规则再开重构线。
- [ ] Harness 独占执行参考加载维护权；Goal 只保留入口和交接，不列另一份 Harness 执行阅读清单。
- [ ] 分类不读完整台账、Guard 操作细节及执行冷路径；门禁/回退/风险触发时读相应参考，安全约束在相关操作前读到。
- [ ] Agent context、LLM Tool/MCP 放入按需参考，保留正向触发、排除条件及原有 MCP 实现/审查顺序；禁用技能与交互偏好不变。
- [ ] 入口、模板和解释引用或校验生成权威规则；逐项列明行为变化及兼容结果，触及原确认边界先获得确认。
- [ ] 整句/段落解释硬匹配改为结构和行为断言，保留精确字段、协议、安全不变量的负向测试。

交接物：接入候选、规则引用一致性结果、加载路由和行为变化清单；不是仅缩短文案。

### D. 评测、发布准备与独立安装授权

- [ ] 保留 WF-01–WF-17 和三等级评测，增补第 4 节 SC 场景；文档自检不算产品契约评测或真实交付验证。
- [ ] 用 A 阶段相同口径重测候选，报告阶段增量/累计数据、读取轨迹、新增开销用途/加载时机及未测限制。
- [ ] 维护工作区内组装必要运行资源的候选包并检查引用闭包；设计历史、活动状态、评测输出、缓存不入包，保留历史，不清理现有安装内容。
- [ ] 提交候选来源、摘要、兼容差异和安装/回滚步骤供审阅；安装同步单独授权，不自动部署、建分支、提交、推送或安装。

## 3. 上下文测量口径

测量的是 Skill 文件上下文体量，不是模型账单、全部提示词开销或成功率估计。前后采用相同场景、宿主和读取边界，保存来源版本、摘要及工具/版本；规范推导清单与实际观察读取轨迹分别标识。

| 阶段 | 截止点 | 加载边界 |
| --- | --- | --- |
| S1 分类 | 首次分类回复及必要确认边界 | 仅分类材料；不得提前读完整台账、Guard 操作细节或执行冷路径 |
| S2 Harness 接入 | 完成交接，未进入首次受治理修改 | 加入该场景接入所需材料，不无触发预读全部参考 |
| S3 首次受治理修改 | 即将执行本轮第一次受治理写入 | 加入能力、宿主、安全操作约束；安全前置条件不可延后 |

- 各场景记录 S1/S2/S3 必读文件及传递引用、触发原因、责任组件、读取时点和证据。移到参考但仍必读的材料仍计入。
- 主表统一按必读文件全文计量，以解析后的真实路径和平台路径规则去重，链接别名只计一次；不同真实文件即便内容相同也不合并，以免掩盖重复材料。实际局部读取另附片段边界及观察记录，不从主表扣除；规定读全文却只读片段属于加载违规。
- 按 UTF-8 原始字节、解码文本 `splitlines()` 行数和 `o200k_base` 对同一未改写文本的 tokens 计量；不去空白、压行或标准化换行，逐文件求和，不计虚构拼接分隔符。
- 累计主表清单为截至该阶段的真实文件集合并集；增量为本阶段首次加入的文件集合。逐文件全文计量再求和，全文只计一次，阶段增量之和等于累计值；实际读取重复次数另报，不冒充已省去的模型开销。
- 每阶段报告前值、后值、差值及累计行数/字节/token；局部读取的附表不能与全文主表混用，防止以片段统计伪装规范已减负。
- 旧审计为 4,715 / 4,991 / 2,070 个增量 tokens（o200k_base，累计 11,776）；仅适用旧安装基线，不是本次前值，也不是实际模型计费。
- 不设任意行数阈值；新增开销说明用途/加载时机，与读取轨迹及行为回归对照。缺 tokenizer 或运行条件如实记未测，不自行安装、不填零、不承诺未测成功率提升。
